2. Check licenses, transitive dependencies, Node/Android/Termux compatibility, admin features that should NOT be exposed, session isolation, source-event format, auto-replies and risky writes.
3. Provide concrete component matrix: reuse/fork/adapter/reject and why; commit SHA/LICENSE evidence; pin only audited dependencies. Retain license notices.
4. Review current Zalo personal-account use/automation restrictions and official alternatives. QR login alone does not prove authorization. Do not bypass anti-abuse measures.

## Step B — Implement safe, useful code now
1. Create isolated TypeScript + Node Gateway module (do NOT replace existing M51 AI or chat service).
2. Build typed connector interface and a feature-complete MOCK connector; account scoped state machine with QR pending/connected/reconnect/needs_relogin. Mock QR must clearly state "SIMULATED", and no remote Zalo login performed.
3. SQLite WAL migrations for accounts, sessions metadata (NOT plaintext secrets), threads, messages, ingest events, disconnect gaps, outbox, job queue; unique per-account scoped identifiers, idempotent insert.
4. Implement synthetic fixtures for 2–3 accounts: DM, group, muted group (mute is test metadata, not source guarantee), self messages, burst, repeated event, network loss, restart.
5. Build a minimal mobile-friendly unified inbox and per-account QR/status panel, showing account of each message, thread, timestamps, connection gaps, and explicit "mock" banner.
6. Add manual-send feature behind NO-REAL-SEND gate. For mock only, require selected account/thread and operator confirmation; no AI action can send.
7. Make inbound storage nonblocking and durable, with backpressure and bounded processing. Never wait for Qwen inference to write an incoming message.
8. Add tests for account isolation, dedup, no-op on duplicate, eventual recovery, gaps, send guard, no leaked secrets, API access restrictions and M51 resource budget. Include real commands + measured output.
9. Provide Termux launch/stop/health scripts or runit service definitions with nonconflicting ports, but do not enable new live services or change existing phone chat until approved.

## Hard security rules
PUBLIC repository. No passwords, QR/session/cookies, private connection.local.json, personal/group messages, addresses, tailnet IP, API key, raw full logs or Zalo account IDs in Git. Never run unknown curl|bash. No root/Magisk, no public API, no Tailscale Funnel, no router port forwarding. Do not weaken thermal/Android security. Maintain original tests and services.
